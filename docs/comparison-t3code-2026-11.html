Harness Manager and T3 Code: how they differ

T3 Code replaces the agents' interface: you chat with Claude Code, Codex and others inside its threads, it makes the branch and the pull request, and you drive it from a phone. Harness Manager manages what sits behind the agents' own terminals: several accounts per tool side by side, their limits and usage, every session they wrote, and one set of MCP servers, skills and prompts written into every tool. They overlap on usage and limits; they do not compete on how you actually work with an agent.

The short answer

T3 Code is an agent client

"An agent harness control surface." A server runs where your agents run and drives them through each vendor's SDK or protocol; desktop, web and mobile apps connect to it. You never open the Claude Code or Codex terminal: the conversation, the diff, the commit and the PR all happen in T3 Code's threads.

  • Best at: one chat surface for ten named agents and any ACP agent, git and PR flow, remote and mobile control.
  • Deliberately not: an account manager. Its FAQ says "I don't think T3 Code is the right place to manage a pile of accounts" and points to an outside proxy.

Harness Manager is an account and setup manager

A desktop app and the hrm CLI around the tools you already use. Each account gets its own folder, so several run in parallel; Start opens the tool's real terminal as that account. It reads every tool's own logs for limits, usage and sessions, and writes shared MCP servers, skills and prompts into each tool's own files.

  • Best at: many accounts per tool, limits and when they free up, sessions across tools and computers, one setup for six tools.
  • Deliberately not: a chat client. It never sits between you and the agent's terminal.
In one line: T3 Code is where you talk to the agents. Harness Manager is where you decide which account they run on, see what they cost and what they did, and keep their setup in step. The niche T3 Code says it will not fill (many accounts per provider) is Harness Manager's centre.

How each works

T3 Code

1You install and sign in each agent's CLI on the machine that will do the work (claude auth login, codex login, …).
2The T3 Code server (t3, or inside the desktop app) runs on that machine and drives the agents: Claude through Anthropic's Agent SDK, Codex through its App Server, others through ACP or their SDK.
3You work in threads: each thread is a conversation with a chosen agent and model, on its own git branch or worktree, with diff review, commit, push and PR from one button.
4Clients connect from anywhere: desktop, web, iOS, Android, through T3 Connect (a Cloudflare tunnel set up by T3's relay), LAN pairing, Tailscale or SSH. The phone is a remote; the computer does the work.
5Usage and Limits read the agents' history on each connected machine and pool accounts per provider.

Harness Manager

1It finds the tools installed and adds their main profiles; Add account creates a new account in its own folder (CLAUDE_CONFIG_DIR, CODEX_HOME, XDG folders, PI_CODING_AGENT_DIR) and signs it in.
2Start opens a terminal running the tool's own CLI as that account; you work in the real Claude Code or Codex TUI. Several accounts run at once.
3It reads each account's logs and limit readings into a local index: 5-hour and weekly windows, the pace forecast, tokens and cost, every session and project, followed live by a folder watcher.
4It keeps MCP servers, skills and prompt files once and writes them into every tool in that tool's format, with a ledger so it only removes its own entries.
5Optionally: API-key accounts through a local router with failover, and several computers merged through a shared folder, a direct mTLS link or a self-hosted encrypted hub.

Differences that matter in use

Your Claude subscription is spent differently

T3 Code drives Claude through Anthropic's Agent SDK. Its own FAQ says this "will drain your 5h limits faster than using Claude Code directly" (a bug its author reported to Anthropic; weekly limits are not affected). Harness Manager starts the real Claude Code CLI, so a session costs what it costs in Claude Code.

Many accounts sit in a zone T3 Code avoids on purpose

T3 Code's FAQ declines account auto-switching because it could risk terms-of-service bans, and sends users with many subscriptions to a self-hosted proxy. Harness Manager runs each account in its own folder and recommends which one to start, but never switches accounts by itself or pools them behind one login. That line is worth keeping explicit in Harness Manager's documentation, since it is exactly what T3 Code's author worries about.

Sessions you started outside the app

T3 Code's history is its threads. Harness Manager's history is everything the tools wrote, wherever you started them: a Claude Code session run from VS Code's terminal on another computer still appears, can be read, followed and resumed.

What leaves your machine

Both keep code and prompts between you and the providers. T3 Code sends anonymous product events by default (provider, model, token counts, hashed ids of your T3, OpenAI and Claude accounts) and relies on its relay for the easy remote path. Harness Manager sends nothing unless you turn a feature on, and its hub is end-to-end encrypted.

Who leads where

T3 Code is clearly ahead on

  • Talking to agents: one polished chat for ten named agents plus any ACP agent, model switching, attachments, voice.
  • Git: branches or worktrees per thread, diff review, commit, push, PR, stacks, six forges.
  • Remote and mobile: drive agents on any machine from a phone or the web.
  • Reach: every desktop OS and architecture, package managers, a large community.
  • Limits for more tools (Cursor, Grok, OpenCode Go) and reset credits.

Harness Manager is clearly ahead on

  • Many accounts per tool, created and signed in from the app, running side by side.
  • Knowing which account to use: forecasts, the Reset Horizon, "use next", the tray.
  • One setup for six tools: MCP servers, skills, prompts, written in each tool's format.
  • Every session from every tool and computer, including ones started outside the app.
  • API-key accounts through a local router with failover and format conversion.
  • Privacy: no telemetry, no account, an encrypted self-hosted hub.
  • Spending your Claude subscription the way Claude Code does.

Using both

They fit together rather than replace each other. A reasonable setup on one computer:

  1. Harness Manager creates and signs in the accounts (for example ~\.claude-work, ~\.claude-personal, ~\.codex-work) and keeps their MCP servers, skills and prompts in step.
  2. In T3 Code, add one provider instance per account, pointing CLAUDE_CONFIG_DIR (or Codex's home) at those folders. T3 Code's docs describe exactly this per-instance folder setting.
  3. Use T3 Code for the conversation, git and PR work, and from the phone. Use Harness Manager's Overview to pick the account with room, and its Sessions page to find past work across tools and computers.

Not verified here: whether sessions T3 Code starts through the Agent SDK land in the account folder in the format Harness Manager's Claude reader indexes. Claude's Agent SDK normally writes the same transcript files as the CLI, so they should appear; worth a quick check before relying on it.

What Harness Manager could take from this

  1. Say "works with T3 Code" out loud. An "Use in T3 Code" action per account that copies the provider-instance settings (name, binary, config folder) would turn T3 Code's biggest user request ("many subs") into Harness Manager's front door. Low effort, high reach.
  2. Pooled view per provider. T3 Code's "one number per window with a segment per account" answers "how much Claude do I have in total" in one glance. Harness Manager shows per account; a pooled line above the Reset Horizon would add the total without losing the detail.
  3. Reset credits. Codex and Claude accounts can carry banked resets; T3 Code shows them and offers "Use reset". If the tools expose this locally, it belongs next to the limit it restores.
  4. More limit sources. OpenCode Go (session, weekly, monthly with an API key) is already in your setup; reading its allowance would light up OpenCode's empty limit rows.
  5. Model price overrides and mapping. T3 Code lets you price unknown models and map preview IDs to released ones; Harness Manager's cost at list prices would benefit for routed and new models.
  6. Package managers. winget and scoop manifests would match how Windows developers install tools, and the Apps page already understands those installers.
  7. Keep the privacy and Claude-accounting advantages visible. No telemetry and native Claude Code accounting are real differences; the README should state them in the first screen.
