01How it works

Each computer is the authority for its own sessions. At home or on the VPN, the phone talks to each paired computer directly over mutual TLS, both sides pinned. Away, the computer and the phone exchange sealed messages through a mailbox on your hub, which sees only sizes and timing. Alerts reach the phone through a small push relay we operate, carrying no content: the phone fetches the details after unlock.

03The safety rules the plan is built around

RuleWhy
A phone never gets the ring key and is never stored as a paired computerComputer pairing today sends the ring key and opens the journal and transcript routes. A phone with Summaries must not be able to read more by knowing a URL.
The computer approves every phone and chooses its grants; the code alone grants nothingA leaked code or hub invite cannot add a phone.
Every action carries an id, the request's state version and an expiry; the computer rechecks just before actingZero stale approvals: if the terminal answered first, the phone gets "already handled".
Stop and reply are never resent automaticallyA second Ctrl+C at an idle prompt can close Claude Code.
Push carries no content; the lock screen says only "A session needs you" unless you turn detail onApple, Google and the relay see nothing about your work.
Revoking a phone cuts its connection, hub token and push handle, and the desktop shows each one acknowledgedA lost phone is shut out within a minute while the computer is on.

06Decisions I need from you

The first option of each is my recommendation.

Where the app's code lives

One repository keeps the API contract, the protocol crate and the app's contract tests changing together in one pull request. A separate repository keeps the desktop's CI lighter.

Pairing and encryption code in the app

The desktop's pairing uses a Rust SPAKE2 implementation with no compatible Dart package. Compiling the same Rust into the app guarantees both sides agree, at the cost of a Rust toolchain in the mobile build. The spike checks it on both phones first.

Where the push relay runs

Docker reuses the hub's deployment and keeps one stack. A Worker is cheaper to run and needs no server, but is a second platform to deploy and watch.

Apple Developer and Google Play accounts

Push, TestFlight and Play testing need them. Whoever owns them owns the listing and the APNs key the relay uses. Without them, phase 0 to 2 still run on your own phones.

Oldest phones supported

iOS 17 brings interactive widgets and the lock-screen features the chosen widgets use; Android 8 covers almost every phone in use and has notification channels.

App name and bundle identifier

The identifier cannot change after the first store upload.

How to start

Parallel is faster. The desktop work doesn't depend on the spikes, except the protocol crate's packaging, which the spike settles in its first days.
