Sidebar, limits and Overview: variations

Working mockups with your numbers from today (8 accounts, 222 projects, 4 live sessions, 11 MCP servers, 251 skills, the seven limits on your Overview). The sidebar menus, the collapsible groups, the doors and the limit bars behave as they would in the app. Nothing here is applied yet; the feedback sheet at the end decides what is built.

Already built, uncommitted on develop: the Skills header spacing and the Antigravity mark at the same size as the other three; MCP servers read from every tool when Harness Manager starts, the list paged at 25, 50 or 100, and an info button on each server that says in which file of each tool it is written, not written, or left alone (the side panel is gone); the Overview without the five crossed-out panels (score and moves, time to first reply, where tokens went, events, fleet health; the two Settings rows that only served them are gone too); an amber dot on the Settings link while a newer Harness Manager waits.

The sidebar

What is wrong with it today, in order of harm:

  • Two kinds of things in one list. Pages you watch (Overview, Projects, Sessions, Accounts) sit among pages you set up once (MCP servers, Skills, System prompts, Apps), with API keys & routing between them. The one gap says nothing about why.
  • The pinned projects push everything down. Three pins and their live counts take as much room as four pages, and they move as sessions start and stop.
  • The counts mean different things. "Today $378.37", "8", "222", "4 LIVE", "11", "251": a cost, a count, a live count and a size, all in the same column and type.
  • Apps is misfiled. It is about the tools' installers and versions, not shared setup, and its update badge is the only warning in the menu.

Limits: one panel instead of two

"Limit burn-down" says how much is left and when it resets; "When limits free up" draws the same resets on a time axis. One panel can say both. Each variation below uses your seven limits and today's resets.

L1One row per account: the bar and the timeline side by side

Limits

tightest window first · bar: what is left · timeline: the open window until it resets, amber tick: runs out at this pace
Keeps both readings on one line, the accounts comparable top to bottom on a shared week.
Costs width: below about 1100 px the timeline drops under the bar.

L2The burn-down rows, with the countdown under each bar

Limits

tightest first · bar: what is left, mark: level at the reset · line: now to the reset, amber: runs out
Keeps the panel narrow, so it still fits beside Live routes; each account is read on its own.
Costs the shared axis: you cannot see at a glance which reset comes first.
